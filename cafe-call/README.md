# 카페 주문 호출 시스템

목소리로 손님을 부르는 걸 대체하는 시스템입니다. 손님이 카운터의 **전용 디스플레이**에 휴대폰
번호를 직접 입력하면, 음료가 나왔을 때 직원이 버튼 한 번으로 **카카오 알림톡**을 보냅니다.

- 진동벨 없음 → 충전·분실·파손·배터리 교체가 전부 사라집니다
- 앱 설치 없음 → 손님은 번호만 누르면 됩니다
- POS는 그대로 → 기존 아이패드 POS 옆에 웹 브라우저로 띄워 씁니다

## 화면 구성

| 화면 | 주소 | 놓는 위치 |
|---|---|---|
| 직원 화면 | `/staff` | 아이패드 POS 옆 (PIN 로그인) |
| 손님 디스플레이 | `/c/<자동생성키>` | 카운터에서 손님 쪽으로 돌려놓음 |

손님 디스플레이 주소는 서버를 처음 켤 때 자동으로 만들어져 터미널에 표시되고,
직원 화면의 **설정**에서도 언제든 볼 수 있습니다.

## 하루 사용 흐름

1. 주문·결제 → 직원이 **[+ 새 주문]** 을 누릅니다 (대기번호 자동 발급)
2. 손님 디스플레이에 `1번 · 휴대폰 번호를 눌러주세요` 가 뜹니다
3. 손님이 번호를 누르고 **확인** → 직원 화면에 `010-****-5678` 로 표시됩니다
4. 음료가 나오면 직원이 **[완료 호출]** → 알림톡 발송
5. 손님이 찾아가면 **[수령 완료]** → 전화번호 즉시 삭제

번호를 안 주는 손님은 **[번호 없이 주문]** 으로 발급하면 됩니다. 그 주문은 손님 디스플레이에
뜨지 않고, 예전처럼 번호를 불러서 안내하면 됩니다.

## 설치

Node.js 22.5 이상만 있으면 됩니다. **설치할 외부 패키지가 없습니다.**

```bash
cd cafe-call
cp .env.example .env      # 값을 채워 넣으세요
npm start
```

터미널에 두 주소와 PIN이 표시됩니다.

```bash
npm test                  # 28개 자동 테스트
```

### 기본값 상태로도 바로 돌아갑니다

`.env` 를 안 만들어도 **모의발송 모드**로 켜집니다. 실제 문자는 나가지 않고 터미널에만 찍히므로,
알림톡 계약 전에 매장에서 흐름을 미리 연습해볼 수 있습니다.
직원 화면 상단에 `모의발송 모드` 배지가 떠 있으면 실제 발송이 안 되는 상태입니다.

## 카카오 알림톡 연결하기

알림톡은 **무료가 아닙니다.** 카카오가 건당 과금하고 발송대행사 마진이 붙어 실제로는 건당
8~9원 수준입니다. 하루 100잔이면 월 2~3만원 정도입니다.

### 준비물

1. **사업자등록증** (필수)
2. **카카오톡 채널** — 채널관리자센터에서 매장 채널을 만들고 비즈니스 인증
3. **솔라피 계정** — https://solapi.com 가입 후 카카오 채널 연동
4. **발신번호 등록** — 매장 전화번호. 알림톡 실패 시 문자로 대체 발송할 때 씁니다
5. **알림톡 템플릿 심사** — 아래 문구로 등록하세요 (심사 2~5영업일)

### 등록할 템플릿

```
[#{매장명}]
#{대기번호}번 주문하신 음료가 준비되었습니다.
카운터에서 찾아가 주세요.
```

- 변수는 `#{매장명}`, `#{대기번호}` 두 개입니다
- 광고성 문구(할인, 이벤트 등)를 넣으면 반려됩니다. 위 문구 그대로 등록하는 걸 권합니다
- 다른 변수명으로 등록했다면 `.env` 의 `TEMPLATE_VAR_STORE`, `TEMPLATE_VAR_TICKET` 만 바꾸면 됩니다

### .env 설정

```ini
NOTIFY_PROVIDER=solapi
NOTIFY_MODE=alimtalk
SMS_FALLBACK=true

SENDER_PHONE=0212345678
SOLAPI_API_KEY=발급받은키
SOLAPI_API_SECRET=발급받은시크릿
SOLAPI_PF_ID=카카오채널ID
SOLAPI_TEMPLATE_ID=심사통과한템플릿ID
```

`SMS_FALLBACK=true` 면 카톡을 안 쓰는 손님이나 알림톡이 실패한 경우 자동으로 문자가 나갑니다.
문자 요금이 별도로 나가지만, 손님을 놓치는 것보단 낫습니다.

### 심사 기다리는 동안

`NOTIFY_MODE=sms` 로 두면 알림톡 없이 **문자만으로** 먼저 운영할 수 있습니다.
발신번호 등록만 끝나면 바로 됩니다. 템플릿 심사가 통과되면 `alimtalk` 으로 바꾸세요.

## 개인정보 처리

손님 전화번호를 받는 시스템이므로 최소한의 장치를 넣어두었습니다.

- **직원 화면에는 마스킹된 번호만** 보입니다 (`010-****-5678`). 원본은 서버 응답에 실리지 않습니다
- **수령 완료를 누르면 번호가 즉시 삭제**됩니다
- 수령을 안 눌러도 `PURGE_AFTER_MINUTES`(기본 120분)가 지나면 자동 삭제됩니다
- 손님 디스플레이에 "알림 발송에만 사용되며 수령 후 자동 삭제됩니다" 안내가 항상 떠 있습니다

매장에도 같은 내용을 안내문으로 붙여두시길 권합니다.

## 태블릿 설정 요령

**손님 디스플레이 기기** (중고 태블릿 한 대면 충분합니다)

- 브라우저로 `/c/<키>` 주소를 열고 **홈 화면에 추가** → 전체화면으로 실행됩니다
- 아이패드: 설정 → 손쉬운 사용 → **가이드 접근**을 켜두면 손님이 다른 앱으로 못 나갑니다
- 안드로이드: **화면 고정(앱 고정)** 기능을 쓰면 됩니다
- 자동 잠금은 **안 함**으로 두세요 (화면 켜짐은 코드에서도 잡아두지만 OS 설정이 우선입니다)
- 충전기를 꽂아둔 채로 쓰세요

**물리 숫자키패드(넘버키)를 쓰고 싶다면**

USB 숫자키패드를 손님 디스플레이 기기에 꽂으면 그대로 동작합니다. 별도 설정이 없습니다.

| 키 | 동작 |
|---|---|
| `0`~`9` | 숫자 입력 |
| `Backspace` | 한 자 지우기 |
| `Enter` | 확인 |
| `Esc` / `Delete` | 전체 지우기 |

## 서버를 어디에 둘까

손님 휴대폰으로 문자가 나가는 구조이므로 **손님이 서버에 접속할 필요는 없습니다.**
매장 안에서만 접근되면 충분합니다.

- **가장 간단**: 매장의 남는 노트북이나 미니PC에서 `npm start` 를 켜두고, 태블릿 두 대를
  같은 와이파이에 붙여 `http://<그 PC의 내부IP>:3000` 으로 접속
- **밖에서도 관리하고 싶다면**: Cloudflare Tunnel 이나 Tailscale 로 노출
- 외부에 열어둘 때는 반드시 `STAFF_PIN` 을 바꾸고 HTTPS를 쓰세요

`data/` 폴더에 주문 DB와 키가 들어 있으니 이 폴더만 백업하면 됩니다.

## 설정 항목

| 항목 | 기본값 | 설명 |
|---|---|---|
| `STORE_NAME` | 우리 카페 | 화면과 알림 문구에 들어가는 매장 이름 |
| `PORT` | 3000 | 서버 포트 |
| `STAFF_PIN` | 1234 | 직원 화면 로그인 PIN — **반드시 바꾸세요** |
| `PURGE_AFTER_MINUTES` | 120 | 전화번호 자동 삭제까지의 시간(분) |
| `NOTIFY_PROVIDER` | console | `console`(모의) 또는 `solapi` |
| `NOTIFY_MODE` | alimtalk | `alimtalk` 또는 `sms` |
| `SMS_FALLBACK` | true | 알림톡 실패 시 문자 자동 대체 |
| `DAY_ROLLOVER_HOUR` | 4 | 대기번호가 1번으로 초기화되는 시각 |

## 구조

```
server.js              HTTP 라우팅, 세션, SSE 연결
src/config.js          .env 로딩, 손님 디스플레이 키 생성
src/db.js              SQLite 스키마 (node:sqlite 내장 모듈)
src/orders.js          주문 상태 전이, 번호 정규화·마스킹·삭제
src/events.js          SSE 허브 (화면 실시간 갱신)
src/notify/solapi.js   솔라피 알림톡/문자 발송
src/notify/console.js  모의발송
public/staff.html      직원 화면
public/customer.html   손님 입력 디스플레이
test/                  28개 자동 테스트
```

외부 의존성이 하나도 없습니다. `npm install` 을 돌릴 필요가 없고, 패키지 취약점 업데이트를
쫓아다닐 일도 없습니다.
